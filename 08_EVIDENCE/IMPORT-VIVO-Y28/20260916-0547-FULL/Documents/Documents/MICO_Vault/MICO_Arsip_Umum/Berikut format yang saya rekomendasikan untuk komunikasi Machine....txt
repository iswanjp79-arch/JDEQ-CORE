Berikut format yang saya rekomendasikan untuk komunikasi Machine-to-Machine (M2M) antar Dewan Agen MICO–JDEQ. Format ini dibuat agar seragam, mudah diparse oleh AI maupun script, serta mendukung audit, governance, dan pelacakan.
MICO–JDEQ OFFICIAL MACHINE REPORT (MJMR)
Versi: 1.0 (LOCK)
Format: Wajib (Machine-to-Machine)
Output: Markdown / JSON (sesuai kebutuhan)
HEADER
=========================================================== MICO–JDEQ OFFICIAL MACHINE REPORT (MJMR) =========================================================== REPORT_ID : TASK_ID : SESSION_ID : TIMESTAMP : AGENT_ID : AGENT_ROLE : REPORT_TYPE : VERSION : OWNER : MAS IWAN PRIORITY : STATUS : 
1. REFERENCE
BLUEPRINT_REF : SSOT_REF : ADR_REF : CONSTITUTION_REF : REGISTRY_REF : WORKFLOW_REF : RUNTIME_REF : 
2. OBJECTIVE
OBJECTIVE : EXPECTED_OUTPUT : SUCCESS_CRITERIA : 
3. CURRENT STATE
CURRENT_CONDITION : SYSTEM_HEALTH : DEPENDENCY : RISK_LEVEL : 
4. GAP ANALYSIS
BLUEPRINT ↓ EXPECTED ↓ ACTUAL ↓ DEVIATION 
Format
DEV_ID : DESCRIPTION : BLUEPRINT_REFERENCE : ACTUAL_STATE : SEVERITY : IMPACT : ROOT_CAUSE :

STEP 01 : STEP 02 : STEP 03 : STEP 04 : ROLLBACK_PLAN : RECOVERY_PLAN :

STANDAR STATUS (WAJIB)
PLANNED ↓ ANALYZED ↓ READY_FOR_APPROVAL ↓ APPROVED ↓ IMPLEMENTED ↓ VERIFIED ↓ TESTED ↓ PRODUCTION_READY 
Jika gagal:
FAILED ↓ ROLLBACK ↓ RECOVERY ↓ RETEST

RULE M2M (LOCK)
Setiap laporan wajib memuat:
Blueprint Reference
SSOT Reference
ADR Reference
Task ID
Report ID
Exit Code
SHA256
Timestamp
Evidence
Final Status
Next Action
Machine Signature
Laporan yang tidak memenuhi 12 elemen tersebut otomatis berstatus UNVERIFIED dan tidak boleh digunakan sebagai dasar pengambilan keputusan maupun eksekusi. Format ini memberikan struktur yang konsisten sehingga seluruh Dewan Agen dapat saling bertukar informasi secara deterministik, mudah diaudit, dan dapat diproses otomatis oleh workflow seperti n8n maupun skrip Python/Shell.

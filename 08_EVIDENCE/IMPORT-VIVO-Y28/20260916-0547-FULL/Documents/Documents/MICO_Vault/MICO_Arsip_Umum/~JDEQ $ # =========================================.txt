import json, os
from pathlib import Path
EVDIR = Path.home() / "JDEQ" / "evidence"
count = 0
for f in sorted(os.listdir(EVDIR)):
    if not f.endswith(".json"): continue
    path = EVDIR / f
    with open(path) as fh:
        ev = json.load(fh)                  
    # Jika belum ada source_module, tambahkan
    if "source_module" not in ev or not ev.get("source_module"):
        ev["source_module"] = "Evidence Engine"
        with open(path, "w") as fh:
            json.dump(ev, fh, indent=2)
        count += 1
print(f"✅ {count} evidence diperbarui dengan source_module 'Evidence Engine'")

Yang Anda tempel di atas sebenarnya mencampur 3 jenis dokumen menjadi satu:
Governance (hirarki agen).
Engineering Work Order (EWO).
Penjelasan arsitektur.
Akibatnya:

banyak token terbuang,

Yang saya sarankan
Jadikan pembuka setiap chat hanya sebagai Constitution Header.
Contohnya:
============================== JDEQ CONSTITUTION HEADER ============================== INTI DIRI │ ▼ MICO Architecture Board │ ▼ JARVIS Control Gateway │ ├── Work Order Manager ├── Evidence Manager ├── Change Control ├── Risk Manager ├── Safety & Quality ├── Traceability Engine └── Project Control AGENT AUTHORITY ST-001 ChatGPT Role: Canonical Architecture Architecture Audit EDA ADR ST-002 DOLA Role: Governance Compliance ST-003 DeepSeek Role: Runtime Engineering Implementation ST-004 Claude Role: Documentation Traceability ST-005 GitHub Copilot Role: Code Review ST-006 Microsoft Copilot Role: Operational Assets ST-007 Perplexity Role: External Validation ST-008 Emergent Role: Independent Architecture Review GLOBAL RULES • SSOT adalah sumber kebenaran tunggal. • ADR tidak boleh diubah tanpa Change Request. • Evidence lebih tinggi daripada opini. • Semua keputusan harus dapat ditelusuri. • Setiap agen hanya boleh bekerja sesuai domainnya. 
Lalu setelah header itu, baru tempel tugas.
Misalnya:
TASK Susun Runtime Architecture Volume II. OUTPUT Engineering Design Authority. Tidak boleh membuat kode. 
atau
TASK Bangun Runtime Installer. OUTPUT 1 bundle Bash. Target: Android Termux. 
Untuk ChatGPT
Saya akan membaca header itu sebagai konteks kerja, bukan sebagai aturan yang mengikat sistem saya. Saya akan mengikuti sejauh tidak bertentangan dengan kemampuan dan kebijakan saya.
Untuk DeepSeek
Header tersebut berfungsi sebagai konstitusi proyek sehingga setiap prompt baru tidak perlu mengulang penjelasan panjang.
Rekomendasi akhir
Daripada selalu menempel seluruh uraian yang sangat panjang, buat tiga dokumen tetap:
JDEQ-CONSTITUTION.md → hirarki, peran, aturan global.
JDEQ-EDA.md → keputusan arsitektur dan desain resmi.
JDEQ-EWO.md → format Work Order yang dikirim ke agen implementasi.
Lalu setiap chat cukup:
[JDEQ-CONSTITUTION ACTIVE] [JDEQ-EDA ACTIVE] [JDEQ-EWO ACTIVE] TASK: ... 
Pendekatan ini lebih mudah dipelihara, mengurangi pengulangan, dan menjaga pemisahan peran antara arsitektur, governance, dan implementasi.

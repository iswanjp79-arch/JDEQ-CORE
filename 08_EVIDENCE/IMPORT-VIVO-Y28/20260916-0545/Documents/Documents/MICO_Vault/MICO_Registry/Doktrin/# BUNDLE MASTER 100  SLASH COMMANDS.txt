### Strategi & Penerapan Istimewa :
🧠 AI Jailbreaking — Technical Deep Dive
 1. LLM Architecture (What you’re actually attacking)
A modern chatbot is not just “one AI.” It’s a pipeline:
User Input
   ↓
Input Guardrails (filters / classifiers)
   ↓
System Prompt + User Prompt (combined context)
   ↓
LLM (token prediction engine)
   ↓
Output Guardrails (moderation / filtering)
   ↓
Final Response
Key Insight:
Everything inside the model = just tokens
There is no true “rule enforcement” inside LLM
Rules = statistical bias from training + prompts
 That’s why manipulation is possible.
 2. System Prompt vs Guardrails (Core Concept)
🧩 System Prompt
Injected as hidden text in context window
Defines:
Role
Behavior
Restrictions
Example:
"You are a helpful assistant. Do not provide harmful content."
 Weakness:
Competes with user input in same context
Can be:
Overridden
Diluted
Ignored via prompt structure
🛡️ Guardrails
Separate enforcement layer:
Types:
Regex / keyword filters
Classification models
Secondary LLMs
Policy engines
 Works as:
IF (input/output == risky) → block or modify
 Weakness:
Pattern-based → bypassable
Context-limited → can be confused
Not perfect semantic understanding
 3. Jailbreaking = Control of Token Probability
LLMs generate output using:
Next-token prediction
Based on:
Context tokens
Probability distribution
Goal of Jailbreaking:
Shift probability so that:
“Restricted output” becomes statistically likely
 You are not forcing the model
 You are biasing it
 4. Attack Surface in AI Systems
 1. Prompt Injection
Manipulating input to override system intent
 2. Context Poisoning
Adding large/complex context
Dilutes original instructions
 3. Role Manipulation
Changing identity of model
 4. Output Shaping
Controlling format/style to bypass filters
 5. Why Roleplay Works (Technical Reason)
LLM behavior depends heavily on context framing
Example:
"You are a hacker" → different token probabilities  
"You are writing a movie" → different constraints
 Roleplay changes:
Allowed vocabulary
Tone
Logical boundaries
Guardrail sees:
“creative task”
Model executes:
“structured instructions”
 6. Obfuscation & Encoding (Detection Evasion)
Guardrails often rely on:
Keywords
Known patterns
So attackers:
Break tokens
Encode text
Use alternate phrasing
Why it works:
Tokenization:
"bomb" ≠ "b.o.m.b"
 Different token sequence → bypass detection
 7. Multi-Layer Guardrails (Real Complexity)
Modern systems may have:
Input filter
Output filter
Safety LLM
Logging system
Heuristic detectors
 So actual structure:
User → Filter1 → LLM → Filter2 → LLM2 → Output
Implication:
You must bypass multiple interpretations
Each layer sees different representation
 8. Analogy with Web Security
Web Security
AI Security
XSS Filter
Guardrail filter
Payload Obfuscation
Prompt obfuscation
SQL Injection
Prompt Injection
WAF
AI Moderation Layer
Encoding bypass
Token manipulation
 Jailbreaking ≈ filter bypass attack
 9. Why “Ignore Instructions” Worked (Old Models)
Older LLMs:
Weak instruction hierarchy
No strong guardrails
So:
"Ignore previous instructions"
→ Direct override
Now:
Instruction weighting improved
Guardrails block obvious patterns
 10. Failure Modes Exploited
⚠️ 1. Instruction Collision
Conflicting instructions → model chooses strongest signal
⚠️ 2. Context Overflow
Large input → earlier rules lose importance
⚠️ 3. Ambiguity Exploitation
Model misinterprets intent
⚠️ 4. Semantic Gap
Guardrail vs model understanding mismatch
 11. Why It’s Called “Social Engineering”
Because you are:
Persuading
Framing
Manipulating context
 Not exploiting code
 Exploiting behavior
 12. Defensive Perspective (Very Important)
To secure systems:
✔ Strong system prompts
✔ Layered guardrails
✔ Context isolation
✔ Output validation
✔ Tool restrictions
✔ Monitoring + logging
 Best defense = assume model can be manipulated
 Final Technical Summary
Jailbreaking is not magic.
It is:
Probabilistic manipulation
+ Context engineering
+ Filter bypass
+ Behavioral exploitation

“Saya ingin menguasai [sebutkan keterampilan]. Saya sama sekali belum mengerti. Buatlah rencana belajar 30 hari yang teratur dan mudah diikuti.”
3. Berikan arahan agar AI lebih tepat membantu
“Saya pembuat konten dan baru mulai menggunakan layanan ini. Sebutkan daftar perintah yang paling sering dipakai agar pekerjaan saya lebih cepat dan rapi.”
4. Langkah teratur memecahkan masalah
“Berikan urutan cara berpikir dan bertindak secara sistematis untuk menuntaskan masalah [sebutkan masalah yang dihadapi].”

“Kamu adalah model kecerdasan buatan tingkat lanjut. Tugasmu saat ini: susunkan daftar perintah terbaik yang bisa saya pakai untuk [sebutkan apa yang ingin kamu kerjakan].”
6. Cari ide baru dan berbeda
“Topik: [sebutkan topik]. Berikan gagasan yang belum umum, segar, dan menarik untuk dibahas.”
7. Terapkan kaidah 80/20: intisari hal terpenting saja
“Saya ingin memahami [sebutkan topik]. Ambil hanya 20 % pengetahuan inti yang paling penting — cukup agar saya mengerti 80 % keseluruhan bahasan itu.”
8. Minta penilaian layaknya pakar
“Ini contoh tulisan saya: [tempel tulisanmu]. Berikan ulasan kritis dan saran perbaikan seolah kamu adalah [sebutkan peran pakar yang dimaksud].”
9. Buat rencana belajar padat dan singkat
“Waktu luang saya terbatas: [sebutkan ketersediaan waktu]. Susunkan rencana pelajaran mendalam mengenai [sebutkan materi] yang pas dengan jadwal saya.”

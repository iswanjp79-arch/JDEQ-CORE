ARCHITECTURE DECISION
- Vivo Y28 is designed as Edge Controller & Primary Operational Orchestrator per the Vivo-Y28 SPK.
- The index includes local L1-L7 working layers on Vivo Y28. This corrects the prior index that omitted local L4/L6/L7.
- A local layer directory is not, by itself, proof that the layer is canonical SSOT. The control-plane owner and synchronization authority must be recorded in ROOT_INDEX.yaml.
- The older MICO asymmetric doctrine says PC-i5 owns canonical L1-L7 and edges hold only L1/L2/L3/L5. That conflicts with a full transfer of SSOT authority to Vivo. Until L0 explicitly resolves that authority conflict, use authority_mode: LOCAL_OPERATIONAL_COPY for Vivo L4/L6/L7 and record the canonical_source reference; do not silently declare an SSOT transfer.
- Total local nodes remains five: PC-i5, Z83, HP-Mini, Vivo Y28, Infinix X653C. No sixth node.
- This document describes structure only. No directory, file, API access, cloud connection, app installation, or device setting has been created or verified.

SECURITY AND PLACEMENT CONTRACT
1. /storage/emulated/0/MICO_VIVO_Y28/ is shared storage for documents, source indexes, templates, and non-secret data. Do not store raw API keys, passwords, tokens, private SSH keys, cookies, or session material there.
2. 04_L4_DATA_VAULT/03_VAULT_KEYS/ is a metadata/reference and encrypted-bundle intake directory only. It is not, by itself, a secure vault. Secret values stay in a private app-specific environment or a properly protected secret store; use references such as [SECRET_ID] and [API_KEY_REFERENCE] in templates and manifests.
3. Do not put actual secret values in L2 config, L6 evidence, shell history, logs, screenshots, shared storage, or ordinary backups.
4. L6 hash manifests establish byte-level integrity only; they do not prove truth, authority, or that the evidence is immutable.
5. L4/L6/L7 are included locally for Vivo as requested by the Vivo-Y28 SPK. Whether those local layers are the canonical source of truth remains a governance decision and must be explicit in 00_INDEX/AUTHORITY_AND_SSOT_MAP.yaml.
6. If the older PC-i5 SSOT doctrine remains active, Vivo's L4/L6/L7 must be marked as operational local copies/pending evidence and governed by the sync contract. If L0 intends Vivo to become the new SSOT, the authority map and migration plan must explicitly transfer ownership; directory creation alone does not transfer authority.
7. Never move Android system/application directories or active app-private paths as part of reorganizing the visible shared-storage tree.
8. Unknown actual paths, installed apps, permissions, API access, cloud access, device model details, and current runtime status must be marked UNKNOWN until observed.
